# Cold-build smoke receipt, 2026-09-25

A cold build of the published patches, exactly as `README.md` describes
it, followed by one run of each tool. Everything below was run on one laptop:
NVIDIA GeForce RTX 5070 Laptop GPU (compute capability 12.0, 8150 MiB),
Windows 11, MSVC 2022 (cl 19.44), CUDA 13.1 (`nvcc` 13.1.80), CMake with
the Ninja generator. Wavs were written to disk only; no speakers,
microphone or camera were used.

The full logs are in `receipts/raw/smoke_2026-09-25/`. In those logs and
in the excerpts below, the directory part of every absolute local path,
system paths such as the MSVC include directory among them, has been
replaced with `<path>/` (each entry of a `;`-separated path list
separately), and Windows line endings were converted to LF; nothing else
was changed. `match.json` and `timing.json` are byte-for-byte as the tool
wrote them.

This receipt is for the published patches: `0001` (patch commit
`0315837`) and `0002` (the converter registration, commit `57b51b3`).
Two earlier cold builds and smoke runs the same morning, of pre-release
revisions `d542389` and `e7b1eb2` of `0001` without `0002`, wrote
byte-identical wavs. Those revisions differ from `0315837` only in source
comments and the example README, and this whole receipt was re-run on the
published revision.

## 2. dynin-u2s: units file -> wav

Vocoder weights: the release asset `emova_u2s.gguf`, 167,497,280 bytes,
SHA-256 `983ff5c1d89a867636a9542e3c0e3b0da451a72b4c075df460dc614cfa97dc84`.
Units: a 79-unit `int32` file produced earlier by a Dynin-Omni-based model
in a separate, unreleased runtime (not by the tools in this release). The same 79
ids are included as text in `raw/smoke_2026-09-25/smoke_units_79.txt`;
running the tool on that text file produced a byte-identical wav (same
SHA-256) to the run on the `.i32` file (`u2s_txt.log`, `wav_sha256.txt`).

What the checks are. On the first call in a process the vocoder runs each
of three stages on both backends and compares the results:

- `enc_p` and the flow: CUDA is kept if its output has cosine similarity
  of at least 0.9999 with the host result and CUDA is faster. Both passed
  (0.99999998 and 0.99999996) and ran on CUDA.
- The generator: CUDA is kept if the signal-to-error ratio of its output
  against the CPU generator's output is at least 40 dB and CUDA is faster.
  It measured 57.15 dB (largest int16 difference 92, first differing
  sample at index 4), so the CUDA generator was used: 86.66 ms against
  2,049.19 ms on the CPU.

These are CPU-vs-CUDA self-consistency checks between two backends
computing the same graph. None of them compares against the PyTorch
reference decoder; no such comparison is part of this release.

Whisper (`whisper-cli -m ggml-base.en.bin -f smoke_u2s.wav -l en`,
`u2s_whisper.log`) transcript of the 3.216 s clip:

```
[00:00:00.000 --> 00:00:03.180]   Uncle Rob grabbed the extinguisher when the alarm went.
```

The sentence is the content of the pre-existing units file, not something
generated in this smoke test; the check is that the vocoder turns those
units back into intelligible speech.

## 3. dynin-t2s-kvblock --compare, one sentence

Model: Dynin-Omni-8.1B Q4_K_M GGUF (`general.name = Dynin Omni`,
`model params = 8.12 B`, file size 4.65 GiB), the same file the fidelity
bench used.

```
dynin-t2s-kvblock -m <path>/Dynin-Omni-8.1B-Q4_K_M.gguf --u2s <path>/emova_u2s.gguf \
    --text "The kettle clicked off and the kitchen went quiet." \
    --steps 48 --block 128 --kv-margin 32 --cfg 2.5 --seed 42 \
    --out <path>/out --wav --compare \
    --whisper-cli <path>/whisper-cli.exe --whisper-model <path>/ggml-base.en.bin
```

Exit 0. Lines from `t2s.log` (verbatim; model-load, per-layer and vocoder
lines omitted here but present in the file):

The log contains the `llama_kv_cache: size = ...` allocation line and zero
`cannot decode batches with this context` lines, so `llama_decode()` ran
against a real KV cache.

Reading:

- The windowed path was 8.71x faster than the dense path for this sentence
  (26,343.1 ms -> 3,023.4 ms, both with 49 forward passes) and produced
  the same 47 unit ids (unit match 1.0000).
- Every seed-invariant output matches sentence 1 of the block 128 / 48 arm
  in `receipts/fidelity_2026-09-22.md`, which ran on the 22 Sep build:
  unit lengths (47, 47), unit match 1.0000, first divergence -1, 49 forward
  passes on each path, both Whisper transcripts and both word overlaps
  (0.3750). The unit ids are not printed, but the two wavs are
  byte-identical to the 22 Sep bench wavs for that sentence (SHA-256
  `1256bf2c...89e1bb` for all four files, `wav_sha256.txt`); both runs
  rendered on the seeded CPU generator from the unit sequence, so the
  unit sequences were the same. The 22 Sep timings for that sentence were
  27,706.8 ms and 3,010.7 ms (9.20x); wall-clock times are expected to
  vary between runs.
- In this process the vocoder's generator gate measured 62.10 dB, but
  the CUDA generator took 3,305.54 ms against 1,986.56 ms on the CPU for
  this 47-unit clip, so the wavs were rendered on the CPU generator
  (`reason=parity_ok,not_faster`). The logs do not show why CUDA was
  slower here; in the `dynin-u2s` process above it took 86.66 ms for a
  longer clip, and in this process the 4.65 GiB model and the 2 GiB KV
  cache were also resident on the GPU. Rendering is outside `total_ms`.
