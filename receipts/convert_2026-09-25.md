# Converter receipt, 2026-09-25

What this checks: that `convert_hf_to_gguf.py` at the base commit, with
`patches/0002-convert-register-Dynin-Omni-architectures-as-LLaDA.patch`
applied, recognises the released Dynin-Omni checkpoint and writes the same
metadata and vocabulary as the Q4_K_M GGUF used for every
`dynin-t2s-kvblock` number in this repository; and that without `0002` it
does not recognise the checkpoint.

What this does not check: the full-weight conversion and the Q4_K_M
quantization were **not** re-run for this release. `--vocab-only` writes
metadata only and reads no weight data, so the tensors of a fresh
conversion were not compared with the file used here.

Everything below ran on the same laptop as the other receipts (Windows
11), with Python 3.13.14, torch 2.12.0+cpu, transformers 5.9.0 and
numpy 2.4.6, and the `gguf-py` package of the llama.cpp checkout. The raw
files are in `receipts/raw/convert_2026-09-25/`, with the directory part
of local absolute paths replaced by `<path>/` and Windows line endings
converted to LF.

## 1. Input files

The checkpoint's non-weight files (config, tokenizer and model code),
taken from a local copy and checked by git blob SHA-1 against
`snu-aidas/Dynin-Omni` at revision
`ebdefada8dfbcfe8d8b21fac6f8fb671d7505d87` (Hugging Face API file listing).
All 13 match (`hf_files_git_blob_sha1.txt`): `README.md`, `config.json`,
`config_resolver.py`, `configuration_llada.py`, `dynin_omni.yaml`,
`generation_config.json`, `modeling_dynin_omni.py`, `modeling_llada.py`,
`prompting_utils.py`, `sampling.py`, `special_tokens_map.json`,
`tokenizer.json`, `tokenizer_config.json`. The four `.safetensors` weight
files and `model.safetensors.index.json` were not in the directory.

`config.json` has `"architectures": ["DyninOmniForConditionalGeneration",
"DyninOmniModelLM"]` and `"vocab_size": 138752`; `tokenizer_config.json`
has `"tokenizer_class": "PreTrainedTokenizerFast"`.

## 2. Without 0002

The base commit's converter (a checkout of `7529fda` with `0001` applied;
`0001` does not touch `conversion/`):

```
python convert_hf_to_gguf.py Dynin-Omni --vocab-only --outfile without_0002.vocab.gguf
```

Exit 1 (`convert_without_0002.log`, verbatim apart from paths):

```
INFO:hf-to-gguf:Model architecture: DyninOmniForConditionalGeneration
ERROR:hf-to-gguf:Model DyninOmniForConditionalGeneration is not supported
```

## 3. With 0002

The cold-build checkout of `receipts/smoke_2026-09-25.md` (`7529fda` +
`0001` + `0002`):

```
python convert_hf_to_gguf.py Dynin-Omni --vocab-only --outtype f16 --outfile dynin-omni.vocab.gguf
```

Exit 0 (`convert_with_0002.log`). The output file is 5,441,718 bytes,
SHA-256 `4759780ec798d285ef0efc006c1f7403b9c78cf7009381825118c9cce8b74221`,
with 0 tensors. Its `tokenizer.ggml.tokens` array has 138,752 entries, of
which 12,380 are `[PAD<id>]` pieces.

## 4. Comparison with the GGUF used here

The reference is the Q4_K_M file used for every t2s run in this
repository: 4,995,107,968 bytes, SHA-256
`5ddb42124205ffbf60fe58653644e9bcd46017088ee1f46b5ef2c1a923a2ef5d`,
converted and quantized on 3 Sep 2026. `cmp_kv.py` reads both files with
`gguf-py` and compares every metadata key (scalars by their raw bytes,
arrays by length and a SHA-256 over their elements). Output
(`cmp_kv_q4km.txt`), in summary:

- 37 keys in the vocab-only file, 38 in the reference.
- 36 keys identical, among them `general.architecture` (`llada`), every
  `llada.*` hyperparameter, `diffusion.shift_logits`, `tokenizer.ggml.model`,
  `tokenizer.ggml.pre`, `tokenizer.ggml.tokens`, `tokenizer.ggml.token_type`,
  `tokenizer.ggml.merges`, the special-token ids (including
  `mask_token_id`) and the chat template.
- 1 key differs: `general.file_type`, 1 (F16) against 15 (Q4_K_M), as
  expected from the two output types.
- 1 key only in the reference: `general.size_label`, which the converter
  does not write in vocab-only mode.

## How the reference file was made

The Q4_K_M file and the F16 file it was quantized from were made on
3 Sep 2026. The F16 file was converted with a local copy of the fork's
converter. Compared with the
base commit, that copy registered the same two architecture names as
`0002`, and forced `vocab_size = max(config value, 138752)` for Dynin
checkpoints. Because this checkpoint's `config.json` already says 138752,
that second change has no effect here, and `0002` leaves it out. The
section above shows that the metadata and vocabulary the patched converter
writes today are the same as in that file.
